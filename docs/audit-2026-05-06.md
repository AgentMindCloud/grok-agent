## TL;DR

The repo is **more built than the meta-state thinks**. Real work exists —
fully-implemented 3 flagship Super Agents, complete v2.15 schema (609
lines), 1468-line safety scanner with 33 checks, 4 production X Money tools
with the cross-tool bridge wired (`x-money-vision-analyzer/data/import_receipts.py`
writes into Tool #1's SQLite at the official AppData path), 22 creator
templates with full Recipe-B compliance, real Pydantic validator with CI
schema-drift guard, working pitch deck + demo script.

The problem is **reconciliation, not implementation**: state-tracking,
docs, marketplace, and CI all under-represent or misrepresent what's
actually shipped. The seam between "code" and "go-to-market" is the
bottleneck. A cold xAI engineer landing today sees an old static page that
shows 1/3 of the agents, with a button that copies text the CLI cannot
consume from a URL.

## The 5 cross-cutting patterns

### Pattern 1 — Claim drift (credibility risk)

Things that are *almost* true but don't reconcile across surfaces:

| Surface | Claim | Reality |
|---|---|---|
| README | 22 creator templates | 22 ✓ — but CLAUDE.md §6 lists 20, ROADMAP lists 20, index.md says "20+" |
| README | "27 named scanner checks" | docs/index.md + docs/for-xai-adoption.md say 15. scanner.py has 33 |
| HANDOFF_LOG.md | 141 rows, top P172 | Phase 4 flagship #1 (Living Narrative Fabric, P93–P100) has **zero rows** despite being shipped; log jumps P103 → P121; lighter Super Agents logged at P151–P154 instead of P117–P120 |
| docs/index.md status table | Phase 1 "in progress" | every other doc says Phases 1–4 done |
| pyproject.toml | declares 2026 OSS stack | Mastra, LangGraph, Stagehand, Crawl4AI, Docling absent (only Mem0/Qdrant/Langfuse/Promptfoo/DeepEval declared) |
| docs/SOURCES.md | reference map | references files that don't exist; ends with leaked AI-assistant copy ("Let me know if you need any adjustments!") |

**Why this pattern matters:** any single drift is forgivable. Together they
let a journalist or xAI engineer say "the project's own state-tracker
doesn't match its marketing" — the worst possible read for a distribution
play that sells itself on provenance and transparency.

**Root cause:** rapid forward progress without back-filling state-tracking.
Phase 6 was opened (`docs/phase-6-kickoff.md`, `creator-program/v2/`) before
Phase 5 was reconciled. CLAUDE.md §16 calls out this exact hazard
("sub-agent self-reports") at the unit level — same disease at the project
level.

### Pattern 2 — The front door is broken

The chain `marketplace → CLI → manifest → install` is the headline UX
promise. Every link has a small break:

```
[GH Pages]  pages.yml uploads marketplace/{index.html,script.js}  (LEGACY pre-Next.js stub)
     ↓     ✗ Next.js out/ never deploys; smoke-test markers reference legacy DOM
[Marketplace UI]  retro-terminal CSS not authored (cinnabar still in globals.css)
     ↓     ✗ TerminalHero, ScanlineOverlay, CommandPalette, TelemetryStrip, InstallButton — defined, not mounted
[Catalogue]  lib/manifests.ts only scans super-agents/ + finance/
     ↓     ✗ 22 creator templates invisible; marketplace shows 11/33 agents
[InstallButton]  copies "grok install this\nManifest: <url>" to clipboard
     ↓     ✗ user must paste into PowerShell — no fetch
[CLI install]  cli/grok-agent.ps1 install accepts local path, -Yaml, -FromStdin
     ↓     ✗ no Invoke-WebRequest path — cannot consume the URL on the clipboard
[Manifest]   user manually downloads YAML file, hands to CLI
[Validate + scan]  ✓ this part works (Pydantic + scanner)
[Install to $env:LOCALAPPDATA\grok-agent\]  ✓
```

**Combined effect:** the headline magic ("paste a URL from an X post → one
command installs") is staged, not real. Each fix is small (S/S/L/S), but
they only pay off together.

### Pattern 3 — Infrastructure ahead of artifacts

Heavy plumbing exists; the artifacts that make it visible don't:

| Plumbing (built) | Missing artifact |
|---|---|
| v2.15 schema (609 lines) + Pydantic mirror + CI drift guard | no public docs page rendering the schema |
| safety/scanner.py (1468 lines, 33 checks) | no published "agents that pass the scanner" badge / list |
| 3 fully-implemented flagship Super Agents | no demo videos (only scripts) |
| `_bridges/registry.json` (real cross-citation contract for all 7) | 4 lighter agents have no code → registry edges are paper |
| `.github/workflows/curation-cadence.yml` (Mon/Wed/Fri cron) | `docs/creator-program/curation-log.md` has zero entries |
| `creator-program/v2/` paid-tier code (`tier_manager.py`, `payment_provider.py`) | no payment plumbing, no sign-up page, no Stripe key story |
| `docs/pitch/xai-partnership-pitch.md` (RFC) + `60-second-demo-script.md` | no canonical marketplace URL the pitch can link to (no `vercel.json`) |
| `scripts/generate-template.py`, `scripts/validate_subagent_report.py` | not invoked from CI; no contributor docs reference them |
| 22 creator templates with full Recipe-B | not visible in marketplace |

**Why this pattern matters:** classic engineer-first prioritization. The
inside is solid; the outside is missing. This is fixable cheaply but only
if recognized as a single coherent gap, not 9 unrelated ones.

### Pattern 4 — Name collisions

Three "creator-program" directories doing different things:

| Path | What it actually is | Should arguably be |
|---|---|---|
| `templates/creator-program/` | Phase-3 outreach + dashboard Python tools (tracker, weekly report, testimonials, launcher.ps1) | `creator-program/v1/` or `tools/outreach/` |
| `creator-program/v2/` | Phase-6 paid-tier code + curation/ package | stays |
| `docs/creator-program/` | one `launch-thread.md` (missing `curation-log.md`, `quarterly-report.md`, `contributor-guide.md` referenced by Phase 6) | stays + back-fill |
| `templates/creator/` | the 22 actual creator agent templates | stays — but easily confused with above |

**Effect:** contributors and xAI reviewers will conflate v1 outreach tools
with v2 paid-tier code. The 22-vs-20 template count drift is a separate
naming issue with the same flavour.

### Pattern 5 — The test gap

- `pyproject.toml` declares `testpaths = ["tests"]`
- `tests/` contains exactly one file: `x-money-integration-smoke.ps1` (PowerShell, not Python)
- Real Python tests live under `creator-program/v2/` — **outside** the configured testpath
- `.github/workflows/validate.yml` runs schema validation + Constitution scan, **does not run pytest**
- 1468-line scanner has zero automated regression coverage
- Pydantic models with `extra="forbid"` and cross-field validators have no unit tests

**Why this pattern matters:** any future scanner change could silently
ship a regression. The 33 checks are the trust story. Trust without tests
is brittle.
