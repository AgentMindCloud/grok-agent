# Tier 3 — moonshot sweep summary

> _Built for xAI, X, Grok and the ecosystem community. ❤️_

The Tier 3 sweep ships **six moonshot surfaces** that turn `AgentMindCloud/grok-agent` from a single-repo agent runtime into a multi-surface platform: a partner-facing artifact pack for xAI, a standalone Python spinoff on PyPI, a live Constitution audit dashboard, an evals portal, a no-code agent generator, and a browser extension that lets anyone install a v2.15 manifest straight from a post on X.

This document is the single page that ties them together: what shipped, where it lives, how to use it, and the v0.2 roadmap for each.

## 1. xAI partnership artifact pack — shipped P182

**What shipped.** A complete partner pack aimed at a single xAI ecosystem engineer reading the repo cold: a one-page pitch, a 60-second video script, a long-form RFC ("Why xAI should adopt v2.15 as the canonical agent manifest"), and a press kit (logos, palette, capsule headers, screenshots).

**Where to find it.**
- `docs/pitch/` — the one-page PDF and source markdown.
- `docs/press-kit/` — logo lockups, color tokens, typography spec.
- `docs/for-xai-adoption.md` — the long-form RFC.
- `docs/whitepaper-manifest-standard.md` — the v2.15 standard write-up.

**How to use it.** Hand the partner the link to `docs/for-xai-adoption.md` first. The pitch page and press kit are downstream artifacts that get used in slide decks or DMs. Every page carries the ecosystem-ally tagline so framing stays consistent across surfaces.

**v0.2 roadmap.** Translate the RFC to Vietnamese for the local creator program, add a recorded 60-sec walkthrough video (currently script-only), and produce a one-pager specifically for the X Money product team that frames v2.15 as the manifest format their creator-facing tools should consume.

## 2. `grok-paradoxes` on PyPI — shipped P183

**What shipped.** A standalone Python library lifted from the Living Narrative Fabric Super Agent: contradiction detection plus authority-weighted reconciliation. Any Python codebase can drop it in to keep multi-source disagreements visible instead of silently collapsing them.

**Where to find it.**
- `packages/grok-paradoxes/` — `pyproject.toml`, `src/`, `tests/`, `examples/`, `README.md`, `CHANGELOG.md`.
- Spinoff section in the root `README.md` documents the install command.

**How to use it.** Locally: `python -m pip install -e packages/grok-paradoxes/`. From PyPI once published: `python -m pip install grok-paradoxes`. The README shows a runnable example: feed it claims with source weights, get back a paradox set with a recommended resolution and a rejected-evidence trail.

**v0.2 roadmap.** Add a streaming API for incremental claim ingestion, ship a Promptfoo eval suite that scores reconciliation quality against a labeled corpus, and publish a sister package `grok-provenance` that bundles the provenance log shape used by the Trust Engine Super Agent.

## 3. Constitution Audit Log dashboard — shipped P183

**What shipped.** A live page at `/audit-dashboard` on the Next.js marketplace that surfaces every Article-level finding the safety scanner has produced across every shipped manifest. Backed by `docs/audit-log.json`, regenerated by `scripts/build-audit-log.py`, drift-checked in CI by `validate.yml`.

**Where to find it.**
- `marketplace/app/audit-dashboard/page.tsx` — the route and per-slug detail view.
- `scripts/build-audit-log.py` — the aggregator (with a `--check` flag for drift).
- `docs/audit-log.json` — the build artifact the dashboard reads.

**How to use it.** Visit `/audit-dashboard` in the deployed marketplace. Each agent shows pass / warn / fail counts and a deep link to `/audit-dashboard/<slug>` for the per-finding view. The dashboard never recomputes scans at request time — it reads the static JSON the CI build wrote, so latency is constant and the source of truth stays in version control.

**v0.2 roadmap.** Add a per-Article timeline view (which Article fired most often this month), a downloadable PDF compliance report per agent, and an RSS feed that publishes every new finding so partners can subscribe to compliance updates.

## 4. Eval Dashboard portal — shipping this sweep

**What shipped.** A new `/eval` route on the marketplace that visualizes the rolling eval history for every Super Agent: pass-rate over time, latency p50 / p95, cost per invocation, and per-metric trends. Backed by `docs/eval-history.json`, written by the new `scripts/build-eval-history.py`, drift-checked by `validate.yml`.

**Where to find it.**
- `marketplace/app/eval/page.tsx` — the index route plus the `/eval/<slug>` detail page.
- `scripts/build-eval-history.py` — the aggregator.
- `docs/eval-history.json` — the build artifact.

**How to use it.** Visit `/eval` to see the agent leaderboard sorted by recent pass-rate. Click an agent to view the time-series chart and the metric-by-metric breakdown. The dashboard makes regression visible: if the Living Narrative Fabric drops below its weekly baseline, the row turns red on the index.

**v0.2 roadmap.** Wire DeepEval scores in alongside Promptfoo so the dashboard shows a faithfulness score next to the pass-rate, add per-PR delta annotations (so a regression points at the merge that caused it), and expose a JSON feed so the marketplace agent cards can display a small badge.

## 5. AI Agent Generator — shipping this sweep

**What shipped.** A `/generate` route that takes a free-form prompt ("a Grok agent that summarizes my replies every morning at 8 a.m.") and returns a v2.15-compliant `grok-agent.yaml` plus a starter folder structure. Server-side it calls a constrained Grok 4.3 prompt that is locked to the v2.15 schema; the output is then run through the same scanner the rest of the platform uses, so a generated manifest cannot ship a Constitution violation.

**Where to find it.**
- `marketplace/app/generate/page.tsx` — the form and result view.
- `scripts/test-generator-prompt.py` — a mock-mode harness for offline CI.
- `safety/scanner.py` — the same enforcement layer applied post-generation.

**How to use it.** Open `/generate`, write the goal in plain language, pick the agent kind (creator, finance, x-native, super-agent), submit. The page returns the manifest, the scanner verdict, and a copy-button for the install command. Failed generations are explained inline ("Article V required disclaimer missing — regenerating with finance template").

**v0.2 roadmap.** Add a guided multi-step wizard for users who do not know which `kind` to pick, support a "remix this agent" entry point that pre-fills the form from an existing manifest URL, and expose the generator as a public REST endpoint so other tools can call it programmatically.

## 6. Browser extension — shipping this sweep

**What shipped.** A Manifest V3 browser extension for Chrome and Edge that detects v2.15 manifest YAML in posts on `x.com` / `twitter.com`, adds a right-click "Install with Grok Agent OS" item, and copies the canonical PowerShell install command to the clipboard. The content script highlights detected manifests inline with a small colored bar so installable posts are visible at a glance.

**Where to find it.**
- `extensions/browser/manifest.json` — the MV3 manifest.
- `extensions/browser/background.js`, `content/`, `popup/` — service worker, detection script, popup UI.
- `extensions/browser/icons/` — toolbar icons.

**How to use it.** Load unpacked in Chrome (`chrome://extensions` → Developer Mode → Load unpacked → pick `extensions/browser/`). Browse X. Any post containing a `version: 2.15` block lights up; right-click the highlight, pick "Install with Grok Agent OS", and the PowerShell one-liner is on the clipboard. Paste into a PowerShell window. The companion extension under `extensions/vscode/` provides the same primitive inside the editor.

**v0.2 roadmap.** Publish to the Chrome Web Store and the Edge Add-ons catalog, add a Firefox MV3 build (waiting on background-script parity), and add a "preview the manifest" panel that shows the scanner verdict before the user copies the install command.
