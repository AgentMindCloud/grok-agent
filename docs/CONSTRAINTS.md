# CONSTRAINTS.md

These rules apply to **every** prompt generated by this skill. Inject them into the "Constraints" section of every prompt. Never water them down.

## The Hard Six

1. **License**: Apache 2.0 in every file. Source files start with the standard Apache 2.0 license header (Copyright 2026 AgentMindCloud). `LICENSE` file at repo root.

2. **Positioning**: Every README, doc, and user-facing string includes a "Built for xAI, X, Grok and the ecosystem community" line (or natural variant). Never frames Grok Agent OS as competing with xAI — always as ecosystem ally.

3. **Platform**: Windows 11 + Google Chrome only. PowerShell-first. Zero macOS, zero Linux-only commands, zero Apple anything in instructions or examples.

4. **Manifest**: Every agent declares `grok-agent.yaml` v2.15. Backwards compat with v2.14 is mandatory — if a v2.14 manifest is dropped in, it must still validate.

5. **Disclaimers**: Every finance, tax, or real-world-action tool includes:
   - "Not financial advice" prominently on UI + README + every export
   - "Not tax advice" on tax-related tools
   - Strong consent gate before any agent takes a real-world action

6. **Local-first + privacy-first**: User data stays on the user's Windows machine by default. Cloud sync is opt-in only. No telemetry without explicit consent.

## The Soft Rules (default unless explicitly overridden)

- **No partial code**: every prompt asks for complete, copy-paste-ready files. Snippet ellipses are forbidden.
- **PowerShell commands**: any shell example uses PowerShell syntax (`;` not `&&`, `New-Item` not `mkdir -p`, `$env:` not `export`).
- **Existing repos untouched**: the 13 original repos (grok-install, grok-install-cli, grok-install-action, grok-yaml-standards, vscode-grok-yaml, grok-agents-marketplace, awesome-grok-agents, grok-docs, x-platform-toolkit, grok-build-bridge, grok-agent-orchestra, universal-spawn, plus older ones) are reference-only. The skill never instructs Claude Code to modify them.
- **GitHub-first execution**: prefer commits + GitHub Actions / Codespaces over local Python builds. The user is on Windows and prior tooling has had compatibility issues.
- **Branding**: cinnabar/parchment palette (Residual Frequencies system) for any visual asset; neon/cyberpunk for GitHub READMEs (capsule-render headers, readme-typing-svg, shields.io badges, Mermaid diagrams).
- **Commit messages**: present tense, imperative, scoped. Format: `phase-N: <verb> <what>` (e.g. `phase-1: add v2.15 unified schema`).
- **Handoff log**: every prompt ends with the exact lines to append to `HANDOFF_LOG.md` (see template).

## Prompt-level constraints (about prompt SHAPE, not output)

- Each prompt is **150–500 words** before the handoff block. Outside that range = too small (combine) or too big (split).
- Each prompt has **one** primary deliverable. List secondary files as "also touch" but the deliverable count is one.
- Each prompt's **Acceptance criteria** has 3–6 testable bullets. Not 1, not 10.
- Each prompt's **Files to create/modify** lists explicit paths. No "and other related files".

## Forbidden phrases in generated prompts

These phrases signal a vague prompt. Never include:

- "and so on"
- "etc."
- "anything related to"
- "as you see fit"
- "use your judgment"
- "boilerplate as needed"

If the skill is tempted to write one of these, the prompt is too broad and must be split.
